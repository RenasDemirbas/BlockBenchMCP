Getting started

Two files: a plugin that runs inside Blockbench, and an MCP server your assistant's client starts. Five minutes from download to the first cube.

Requirements

WhatVersionNotes
Blockbench5.2 or newer5.1.4 works too; tools that need 5.2 say so instead of failing silently.
Node.js18 or newerRuns the server. node --version to check.
MCP clientanyClaude Desktop and Claude Code are tested; any client that starts stdio servers works.

Install

  1. Download blockbench_mcp.js and mcp-server.js from the latest release, or the zip with both. The server has its dependencies bundled: no npm install.
  2. Put them in a folder that stays put. Blockbench loads the plugin from that path, and your client starts the server from it.
  3. In Blockbench open File → Plugins, choose Load Plugin from File in the top-right menu, pick blockbench_mcp.js and accept the prompt. Blockbench MCP Bridge by Renas Demirbas appears in the list.

Register the server

Claude Code

claude mcp add --scope user blockbench -- node /path/to/mcp-server.js

Claude Desktop

Add this to mcpServers in %APPDATA%\Claude\claude_desktop_config.json (macOS: ~/Library/Application Support/Claude/), then quit Claude Desktop completely and open it again.

"blockbench": {
  "command": "node",
  "args": ["C:\\path\\to\\mcp-server.js"],
  "env": { "BB_BRIDGE_PORT": "8188" }
}

Other MCP clients

Any client that starts stdio servers: command node, argument the absolute path to mcp-server.js. Several clients can run at the same time. The first server to start becomes the bridge and the others relay through it.

Check the connection

With Blockbench open, ask your assistant:

Check the Blockbench status.

get_status answers with "connected": true, the Blockbench and plugin versions, and a features list showing which Blockbench 5.2 features your install has. Not connected? See Troubleshooting.

Your first model

Ask for one step at a time and look at each result. It is faster than fixing everything at the end:

Make a wolf in the Bedrock entity format. Build only the skeleton and the shape in grey cubes first and show me three views.

Then: "Make the legs a bit longer", "now texture it", "add a walk cycle", "export it to my desktop". Every step lands in Blockbench's undo history, so Ctrl+Z takes back anything you don't like. More in Workflows.

Coordinates

  • 1 unit = 1/16 block. Y is up; the ground is y = 0.
  • +X is east, −Z is north. Entities face north; the north camera preset shows the front.
  • Rotations are degrees in ZYX order. +X swings a hanging limb forward.

Headless mode

With BB_HEADLESS=1 in the server's env, Blockbench doesn't need to be open. When a tool needs it, the server starts it with the window hidden, waits for the plugin (about 5 seconds) and runs the tool. Screenshots render offscreen.

"env": { "BB_BRIDGE_PORT": "8188", "BB_HEADLESS": "1" }
  • blockbench_window shows and hides the window, with or without headless mode.
  • BB_EXECUTABLE points to a non-default install; BB_LAUNCH_TIMEOUT_MS (90000) caps the wait.
  • Hiding the window works on Windows. On macOS and Linux Blockbench starts visibly; on a Linux server without a display, point BB_EXECUTABLE at a script that runs it under xvfb-run.

Changing the port

The bridge uses port 8188. To change it, set BB_BRIDGE_PORT in the server's env and Settings → General → MCP Bridge Port in Blockbench to the same number.

Updating

  1. Replace both files with the new release.
  2. Restart Blockbench, then restart your MCP client. A running server keeps the old version.

plugin_version in get_status shows what is loaded.
