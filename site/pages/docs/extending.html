Adding tools

Another Blockbench plugin can give the assistant its own tools, with no server restart. And if you want a tool in Blockbench MCP itself, here is how the code is laid out.

From your own Blockbench plugin

Register through window.BlockbenchMCP. Listen for blockbench_mcp_ready too: it covers a plugin that loads before this one and re-adds your tool when the bridge plugin reloads.

let tool;
function addTools() {
  tool = BlockbenchMCP.registerTool({
    name: 'count_cubes',
    title: 'Count cubes',
    description: 'Count the cubes in the open project, optionally only those whose name contains a filter.',
    inputSchema: { type: 'object', properties: { filter: { type: 'string' } } }, // JSON Schema
    annotations: { readOnlyHint: true },
  }, ({ filter }) => ({ count: Cube.all.filter((c) => !filter || c.name.includes(filter)).length }));
}

Plugin.register('my_plugin', {
  onload() {
    if (window.BlockbenchMCP) addTools();
    window.addEventListener('blockbench_mcp_ready', addTools);
  },
  onunload() {
    tool?.delete();
    window.removeEventListener('blockbench_mcp_ready', addTools);
  },
});
FieldRules
name1–64 characters of A-Z a-z 0-9 _ - .. A name that a built-in tool or another plugin already uses is refused.
descriptionRequired. It is all the assistant reads to decide when to call the tool, so say what it does and what it returns.
inputSchemaOptional JSON Schema with type: "object". Arguments are not validated against it; check them in the handler.
handlerMay be async. A string comes back as text, anything else as JSON. Put PNG data URLs in __image (or an array in __images) to return pictures. A thrown error becomes the tool's error message. Calls time out after 120 seconds.
return valueregisterTool returns an object whose delete() removes the tool again.

A built-in tool

The code is split by layer, so a new tool touches three places:

LayerFolderHolds
Schemaserver/src/tools/The tool's name, description and parameters. It forwards to a plugin command of the same name.
Handlerplugin/src/handlers/The Blockbench side: read and write Blockbench state, record undo, fail with a message that says how to recover.
Mathplugin/src/rig/, mesh/, texturing/Pure functions with no Blockbench globals: skinning, deformers, PBR maps, seam blending.

Then add checks to a scripts/verify-*.mjs script, which runs against a live Blockbench, and list the tool in the README and the changelog. The full checklist is in CONTRIBUTING.md.

Trying it without restarting your client

An MCP client fixes its tool list when it starts the server. scripts/call-tool.mjs starts a fresh server for one call instead:

npm run build
node scripts/call-tool.mjs eval_code '{"code":"setTimeout(() => Plugins.devReload(), 300); \"ok\"","undo":false}'
node scripts/call-tool.mjs my_new_tool '{"some":"argument"}' --images e2e-output/tmp
