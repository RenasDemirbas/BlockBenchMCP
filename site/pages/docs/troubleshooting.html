Troubleshooting & security

Most problems are a plugin that is not loaded, two different ports, or a client still running the old server.

"Blockbench is not connected"

  1. Is Blockbench running? (Or turn on headless mode and the server starts it.)
  2. Is Blockbench MCP Bridge listed and enabled under File → Plugins?
  3. Is the port the same on both sides? BB_BRIDGE_PORT in the server's env and Settings → General → MCP Bridge Port in Blockbench, 8188 by default.

Updated, but nothing changed

Restart your MCP client. The running server process keeps the old file until the client starts it again. get_status shows the plugin_version Blockbench has loaded.

Long operations time out in the background

Browser engines slow timers down in background windows. The plugin works around this; timers.unthrottled in get_status should be true. If it is false, bring Blockbench to the front.

The model looks wrong

  • Blank screenshot: a fully transparent texture makes faces invisible. The tools warn about it; paint the texture or give it a fill colour.
  • Washed out, or a fine grid: Blockbench's brightness and pixel_grid settings, not the texture.
  • Right as an image, wrong on the model: ask for uv inspect; it finds faces that share UV space, stretched or rotated rects and see-through pixels.
  • A skinned mesh tears at a joint: vertex_weights smooth near that bone, and inspect for vertices that follow no bone.

Logs

  • Claude Desktop: %APPDATA%\Claude\logs\mcp-server-blockbench.log
  • Blockbench: Ctrl+Shift+I → Console, lines starting with [MCP]

Still stuck? Open an issue with the get_status output.

Security

Whatever reaches the bridge can edit your models and run code in Blockbench, so the bridge is what the design protects.

ThreatDefence
Another device on the network connectsThe bridge binds to 127.0.0.1 only.
A website in your browser connects to the local portBrowsers always send an Origin header and a page cannot fake it. Only connections without one (the server's own relays, Node scripts) and the Blockbench window (file://) pass the handshake. Since 1.6.1; older versions are unsafe.
eval_code freezes BlockbenchNode modules that open Blockbench's blocking permission dialog are refused before the code runs.
A failed batch leaves a half-built modelEvery tool writes to the undo history; batches that fail halfway remove what they created.
A plugin's tool shadows a built-in oneTaken names are refused.

Programs already running under your account can reach a local port like any MCP client; they already have your permissions, so this adds no risk. There is no telemetry and no update check: neither part opens a connection other than the local bridge.

Found a vulnerability? Please report it privately through GitHub's private vulnerability reporting, not as a public issue. Details in SECURITY.md.
